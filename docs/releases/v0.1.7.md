# v0.1.7 — 2026-09-17

Security and signing-anchor release. No CLI verbs changed.

## Signing anchors

The committed GPG primary pin was updated after v0.1.6 for the replacement
release certificate. This pack re-verifies that existing primary-role
OpenPGP fingerprint; it does not introduce another GPG rotation.

The minisign trust anchor and matching NDJSON receipt are regenerated together
from the current exported public key with `make release-insert-anchors`. The
committed minisign value uses `minisign-public-blob-sha256-v1`; the native key
ID remains operator correlation metadata rather than the trust anchor.

Reviewers can recompute both records from the exported public files without
consulting ambient keyrings:

```sh
decernor fingerprint decernor-release-signing-key.asc \
  --class public --kind gpg --format json --path-mode none --gpg-role primary
decernor fingerprint decernor-minisign.pub \
  --class public --kind minisign --format json --path-mode none
```

The signed release payload includes the release notes and both committed pin
files. The ceremony stages notes, then anchors, before checksums and signatures.

## Build and security baseline

- Go 1.26.6 and Goneat v0.6.0.
- Fulmen Crucible v0.4.19; direct module versions otherwise remain unchanged.
- Digest-pinned v0.5.6 toolbox runner and immutable workflow Action revisions.
- Pinned govulncheck, gosec, and gitleaks checks in CI and release.
- Full module-graph license inventory with exact runtime-report reconciliation.

The gate controls reject scanner failures, secret findings, disallowed or
incomplete license reports, release publication-policy drift, and required
bootstrap tool failures. CI workspace-boundary handling and oversized SSH
length parsing also have bounded regression coverage.

## Verification sequence

1. Verify signed checksum manifests.
2. Verify archive, release-note, and staged pin-file checksums.
3. Recompute fingerprints from the exported public files and compare them with
   `expected-fingerprints.txt` and `expected-fingerprints.ndjson`.
4. Confirm the GitHub release remains a draft until the attended publish step.

Package-manager updates follow only after the signed release is verified,
published, and anonymously downloadable.
