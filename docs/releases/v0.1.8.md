# v0.1.8 — 2026-09-24

This release adds public signing-anchor verification. Dependencies and the
committed GPG and minisign anchors are unchanged from v0.1.7.

## Verify committed anchors

Consuming repositories can commit an independently trusted anchor pair and
verify downloaded public exports directly. Use an already-trusted Decernor
installation, not the binary from the release being checked. For first use,
establish the pins out of band, for example from a signed tag whose signature
you checked with a key you already trust:

```sh
decernor fingerprint verify \
  --anchors keys/expected-fingerprints.txt \
  --anchors-ndjson keys/expected-fingerprints.ndjson \
  --gpg decernor-release-signing-key.asc \
  --minisign decernor-minisign.pub
```

The command accepts named regular public files only. It checks TXT/NDJSON
agreement and the embedded schema, recomputes the GPG primary fingerprint and
minisign public-blob SHA-256, and evaluates expiry and revocation. GPG
verification requires `gpg` on `PATH`; without it the command exits 2. It
runs GPG in an isolated temporary home, does not use your keyring or agent,
and makes no network calls. NDJSON results report status and
validity without fingerprints or paths. Use `--format json` for one JSON array.
`--as-of` accepts an RFC3339 time for repeatable expiry evaluation;
`--allow-expired` permits an otherwise matching expired primary key.
A primary-key revocation present in the supplied file is fatal; a revoked
subkey does not change the primary result. A file or directory literally
named `verify` must be passed as `./verify` to use the existing fingerprint
command.

Exit codes are 0 for match, 2 for input or helper failure, 3 for unsafe or
ambiguous input, 4 for invalid anchor pair, 5 for fingerprint mismatch, and 6
for fatal validity. See the [verification contract](../decisions/ddr-0004-fingerprint-verification-contract.md)
for the full result format.

## Release provenance

The maintainer creates a signed Git tag for the reviewed release commit and
verifies the tag locally and on GitHub before signing assets. The signed
release set includes archives, these notes, the unchanged anchor pair, and
signed checksum manifests. First match the downloaded public exports to the
independently trusted anchor pair with the command above. Then use those
verified exports to verify checksum signatures and manifest digests, and
compare the staged release anchors with the trusted pair. A downloaded anchor
pair cannot authenticate its own keys; `fingerprint verify` compares public
files with anchors and does not verify signatures.
